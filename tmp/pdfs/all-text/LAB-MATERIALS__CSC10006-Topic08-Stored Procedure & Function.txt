2 Detailed Instructions 
2.1 Stored Procedure
2.1.1 Introduction  
When we create an application with Microsoft SQL Server, the Transact-SQL programming
language is the primary language for communication between the application and the SQL
Server database. When we create programs with Transact-SQL, two main methods can be used
to store and execute programs:
 We can store running script locally and create applications to send commands to SQL 
Server and process the results.
 We can store running script as stored procedures in SQL Server and create applications to
call and execute stored procedures and process the results.
Characteristics of Stored-procedures in SQL Server:
 Accept input parameters and return values contained in the parameters to call procedures 
or process them accordingly.
 Contain program commands to execute operations in the database, including calling other
procedures to execute.
 Return status values to call procedures or perform operations to indicate whether the 
execution is successful or failed; if failed, the reason for the failure.
Stored procedures differ from functions in that their return value is not contained in the name 
and they are not used directly in expressions. We must use Transact-SQL command EXECUTE
to call stored procedures.

Stored procedures have advantages over locally stored Transact-SQL programs:
 Stored procedures allow for program adjustments: We can create a stored procedure once
and store it in the database, and in the program, we can call it with any number of times.
Stored procedures can be identified by someone who created them, and their changes are
completely independent with the source code of the program.
 Stored procedures allow for faster execution: if the processing requires a large Transact-
SQL source code segment or the execution is repetitive, stored procedures execute faster
than executing a series of Transact-SQL  commands. They are parsed and optimized
during  the  first  execution  and  a  compiled  version  of  them  is  stored  in  memory  for
subsequent calls, meaning that in subsequent executions, they do not need to be parsed
and optimized again, but they will use the previously compiled results, which means that
in subsequent executions, they will use the previously compiled results.
 Stored procedures can reduce network transmission congestion: Suppose a processing
uses a large number of Transact-SQL commands, and the execution goes through each
line of command, so executing stored procedures will be shorter, because when not
executing them, we have to send the command stream over the network, which will lead
to network congestion.
 Stored procedures can be used in machine security issues: because users can be assigned
permissions to use these stored procedures, even if they are not allowed to execute them
directly.
2.1.2 Syntax  
A Stored procedure is defined including the following components:
 The name of the stored procedure
 Parameters
 The body of the stored procedure: including the Transact-SQL commands to execute the
procedure.

2.2 Function
2.2.1 Introduction  
In SQL Server, we can write functions and return values. The types of functions that can be 
written are as follows:
 Functions that return scalar values: varchar, int, ....
 Functions that return table values: inline table-valued
2.2.2 Syntax  
  Create function return scalar value:
CREATE FUNTION function_name ( [@parameter_name parameter_data_type] )
RETURNS [return Data-type] /*Returns has ‘s’ */
AS 
Begin
return ([scalar value])
End
  Create function that returns a table:
CREATE FUNTION function_name ( [@parameter_name parameter_data_type] )
RETURNS table
AS
return [select command]
2.2.3 Example  
Example 5: Write a function to calculate age based on date of birth
-- Create function
CREATE FUNTION fTinhTuoi ( @ngaysinh datetime )
RETURNS int
AS
BEGIN
return year(getdate()) – year(@ngaysinh)
END
